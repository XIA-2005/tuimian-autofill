## 2. 本轮已经直接解决

### G07a：生产异步依赖执行与测试注入困难

新增 `src/core/dependency-executor.ts`，由 `runFillPipelineAsync` 接入正式内容脚本：

- 每个任务等待其父任务；独立根任务可以继续推进。
- 就绪等待涵盖disabled/readonly/aria-busy、实际选项和可选声明式readySelector；总时间有上限。
- 父项稳定后才放行子项；对子控件重新解析，允许页面有证据地替换旧子控件后填写新控件。
- 父节点被替换/改值、原轮取消/档案变化后停止后续依赖写入；被阻塞目标不能再被通用链填写。
- 父字段新增关联错误也阻塞后代，独立字段仍继续。
- 正式内容脚本首次填写、延迟补填、保存恢复都使用异步入口，等待后再检查原轮；loadProfile之前捕获原轮，避免旧读取冒用新轮。

没有给正式扩展增加测试契约消息接口。`test/dependency-e2e.mjs` 复制真实dist到临时目录，只在临时content构建中静态追加测试适配包；使用真实生产内容脚本和driver，HTTPS测试页面全部由本地拦截返回。

八个浏览器场景：

| 场景 | 核心断言 |
|---|---|
| normal | 父选择→260ms后新院校控件→院校确认→新专业控件，顺序正确，旧节点未写 |
| same | 父已同值，零父写事件，合法子项仍填写 |
| conflict | 父已有不同值，子项零写，独立邮箱填写 |
| empty | 父资料为空，子项零写，独立邮箱填写 |
| timeout | 父持续忙碌，有界结束且子项零写 |
| cancel | 填写中修改档案，旧轮子项零写 |
| replace-parent | 父节点被同ID新节点替换，旧父授权不能继续 |
| parent-rejected | 父值保留但出现显式关联错误，子项零写 |

正例还检查最终失败数为0；不是仅断言DOM值正确。测试资源全部本地，未知请求计数为0。

### 顺带修复的实际问题

1. **代码与名称比较导致正确结果误报失败**：新浏览器正例先复现failed=3；合同expectedValue使用已由driver验证的原生DOM表示后，三个代码型选择不再误判。radio结果引用也指向实际选中项。
2. **旧终态消息更改完成状态**：`terminalize`在accept失败后立即返回，不再修改terminal标志；旧run和旧seq均有硬断言。
3. **显式关联错误未识别**：原归因只看文案是否含内部ID。新增对aria-describedby/aria-errormessage直接关联容器的支持，用真实扩展“parent-rejected”验证。
4. **700ms终态回调冒用新轮**：结果发送闭包使用捕获的fillCtx并核对有效性；不再读新activeRunId授权旧回调。

这些是局部修复，不表示整个跨frame协议、所有driver、所有权生命周期已经全部完成。
