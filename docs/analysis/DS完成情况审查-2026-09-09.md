## 3. 关键源码原因

- `src/core/control-drivers.ts:29` 仍用首个 ID/选择器；`:80` 的文本写入及 radio/select 等路径没有统一冲突/同值门禁。新候选编译不能自动保护旧执行链。
- `src/core/filler.ts:678` 的新比较明确排除了日期、popup、compose 等分支，合同和部分专用路径也绕过。`:309` 的所有权是 Document 级 Map，`:404` 清除再依赖 filled 属性；`:451` 恢复未验证节点连接和当前作用域。
- `src/core/fill-merge.ts` 只认领部分状态/元素，跳过项仍可能与合同成功项重复；专用表格前置写入不受普通循环的排除回调完整约束。
- `src/background/index.ts:41` 仍固定 1200ms 收口。`:134` 用当前 runId 填补缺失 runId，使无作用域消息被接纳。没有参与者终态协议。
- `src/content/index.ts:1959` 将 lastResult 换成序列化结果；`:1910` 的稳定校正依赖元素引用，通常已无 el。延迟回调使用可变的全局当前快照，未完整捕获原轮次；`:1088` 恢复路径还能在失效后用旧 profile 建新轮次。
- `src/core/task-executor.ts:33` 的 stableReadback 和 `:94` 的 attributableValidationError 主要由测试调用，没有覆盖单项生产写入；后者存在无关联时回退到任意可见错误的逻辑。
- `src/core/fill-task.ts:49` 的 routeKeyFor 丢 hash、保留路径内容并全部小写；作用域比较还漏 packageVersion。dependsOnIds 只有类型，不能视为依赖执行已完成。
- `test/regression/run-e2e.ts:17` 的按钮监听安装在表单生成前；读取 clicks[id] || 0 掩盖了未安装监听器。
- `test/regression/observer.ts` 只靠事件观察不足以检测静默 setter；重复 name 的快照还需要稳定元素身份，不能用名称覆盖。

行号针对本次快照；实施时以函数名和证据 SHA-256 核对，禁止机械按旧行号改动。
