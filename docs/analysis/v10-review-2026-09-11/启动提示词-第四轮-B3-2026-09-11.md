## 1. B-3 规格

### 1.1 问题（三条证据，均已复核）

**(a) 代码证据** —— `tools/v10-hashes.cjs` 的 tree 快照给 88 个存量文件写了 `sha256`，**但没有任何代码路径读过它**。全仓 `tree.files` 只出现 4 次：写入 `:87`、输出 `:91`、判存在 `:109`/`:142`。`check()` 的漂移循环只遍历 `expected`（基线 135 ∪ 签名）。

**(b) 现场实测** —— 审查者往 `.github/workflows/offline-gates.yml` 追加一行后跑 `check`，输出与改前**逐字相同**（`131|3|1|15|0`），无 DRIFT / DECLARED-NEW / UNSIGNED-NEW。

**(c) 本轮已真实走过此洞** —— `[N-3]` 改了 `.github/workflows/offline-gates.yml`，而它**不在任何 touch-list 里**，`check` 一声不吭。**即 CI 门禁的定义可被静默削弱。**

**(d) 可行性预检（审查者探针 `probe-b3-precheck.cjs` 实测，重要）**：

```
tree 文件数 88 | 自 9a0f40a 改动 23 | 受控层 135
=> B-3 会报出的 tree 改动：1 项
   TREE-DRIFT  .github/workflows/offline-gates.yml
判定：报项数量可控 → 规格可行，不会噪音淹没
```

**所以这项检查上线后只会多出一行，不是洪水。** 这也反过来确认：tree 里其余 22 个改动文件要么在受控层（基线/签名），要么未被改动。

### 1.2 改法（精确到代码）

在 `check()` 内、现有"未声明新文件"循环**之后**追加：

```js
// === B-3：tree-only 文件的"已改且未声明"可见性 ===
const ref = tree.grandfather || GRANDFATHER_REF;
// 注意：必须带 -c core.quotePath=false，否则中文名文件会被八进制转义而永不匹配（你自己发现的坑）
const dirty = new Set(gitLines(`git -c core.quotePath=false diff --name-only ${ref} HEAD`));
const declaredMod = []; const treeDrift = [];
for (const p of Object.keys(tree.files).map(norm)) {
  if (expected[p] !== undefined) continue;   // 已进受控层 → 走既有漂移检查，此处不重复报
  if (!dirty.has(p)) continue;               // 未改动 → 不报（未提交的 build 产物不进 diff，天然无噪音）
  if (touchRes.some((r) => r.test(p))) declaredMod.push(p);
  else treeDrift.push(p);
}
```

输出与退出条件同步：

```js
console.log(`[v10-hashes] check：受控一致 ${ok} | 漂移 ${drift.length} | 缺失 ${missing.length} | 新文件已声明 ${declared.length} | 未声明 ${unsigned.length} | 存量已声明 ${declaredMod.length} | 存量漂移 ${treeDrift.length}（基线+签名 ${Object.keys(expected).length} ∪ 树 ${Object.keys(tree.files).length}）`);
for (const d of declaredMod) console.log('DECLARED-MOD ' + d);
for (const d of treeDrift)   console.log('TREE-DRIFT ' + d);
console.log('[说明] 漂移/缺失/未声明/存量漂移 非零在 RD-7 待审态下属预期；签名后应归零');
process.exit(drift.length || missing.length || unsigned.length || treeDrift.length ? 1 : 0);
```

**三个设计要点，请勿省**
1. `expected[p] !== undefined` 必须跳过——否则已签名的文件会被重复报成存量漂移；
2. **`-c core.quotePath=false` 必须带上**——`tree.files` 里有大量中文名文档，漏了这条，B-3 自己就会重演你上一轮发现的那个逃逸漏洞；
3. `DECLARED-MOD` 与 `DECLARED-NEW` **分开报**——存量改动不是新文件，混在一起会让"新文件"这个分类失真。
