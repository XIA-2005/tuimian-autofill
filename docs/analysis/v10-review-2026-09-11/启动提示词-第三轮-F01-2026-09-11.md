## 1. 第一件事：B-3（约 5 行，最后一个工具项）

### 问题

`tools/v10-hashes.cjs` 的 tree 快照为 88 个存量文件写了 `sha256`，**但没有任何代码路径读过它**（全仓 `tree.files` 只有 4 处：写入 `:87`、输出 `:91`、判存在 `:109`/`:142`）。`check()` 的漂移循环只遍历 `expected`（基线 135 ∪ 签名）。**结果：修改任意 tree-only 文件，`check` 完全无感。**

**现场实测（已坐实）**：我往 `.github/workflows/offline-gates.yml` 追加一行后跑 `check`，输出与改前**逐字相同**（`131 | 3 | 1 | 15 | 0`），无 DRIFT / DECLARED-NEW / UNSIGNED-NEW。

**本轮已真实走过这个洞**：`[N-3]` 改了 `.github/workflows/offline-gates.yml`，而它**不在任何 touch-list 里**（F03 只有 `test/*` 与 `.gitattributes`），`check` 一声不吭。**这是 CI 门禁的定义本身可以被静默削弱。**

### 要求

不要无脑全量比对（tree 含构建产物 `test/real-e2e.cjs`，会比出 build 噪音）。用 `tree` 模式**已经在算**的 `dirty` 集合，在 `check()` 里与"未声明新文件"同一循环之后追加：

```js
const dirty = new Set(gitLines(`git -c core.quotePath=false diff --name-only ${GRANDFATHER_REF} HEAD`));
for (const p of Object.keys(tree.files)) {
  if (!dirty.has(p)) continue;                                  // 未改 → 不报（未提交的生成物不进 diff，天然无噪音）
  if (touchRes.some((r) => r.test(p))) { declared.push(p); }    // 已在某卡 touch-list → 视同已声明
  else { treeDrift.push(p); }
}
// 输出 TREE-DRIFT <path>，并计入 process.exit 的条件
```

**验收**

1. `update` 前先跑 `check`：必须把 `.github/workflows/offline-gates.yml` 报为 `TREE-DRIFT`（它就是本轮改过、未声明的那个），并把该路径补进 F03 的 touch-list 声明 → 报项归零。
2. **负向自检**：临时改一个 tree-only 且未声明的文件（如 `.gitignore`）→ 必须 `TREE-DRIFT` + exit 1；还原 → 归零。记录命令与退出码。
3. 顺手把审查者提的两条小改做了（非阻塞，同批）：
   - `check` 输出末尾加一行说明：`[说明] 漂移/缺失非零在 RD-7 待审态下属预期；签名后应归零`（防新读者误判为事故）；
   - 把"**签名前必须跑一次 `check` 并把输出贴进账本**"写成显式流程（现在是隐含的）。

> **若你判断噪音风险不可接受**：必须（a）把该限制作为**具名残留限制**写进任务书与账本，附完整 88 文件清单 + "其中 11 个为代码/治理类"的明示；（b）取得**用户书面接受**。仅口头默认不可。

## 3. 第三件事：F01 —— **oracle 草案先行**

F01 的卡文要求不变（任务书 §3-F01，已吸收 P1–P9 + 我第二轮的三条前置）。**开工顺序有一条硬约束：oracle 草案必须先出、先签、先送 GPT，之后才允许 bench 用已冻结的期望表跑绿。**

### 3.1 oracle 草案（六字段，P6 细化）

落 `docs/analysis/v10-review-2026-09-11/oracle-draft-F01.json`：

```
{

  档案源值        (profile 路径 + 原值, 如 education.startDate = "2022-09"),
```

**自足性硬要求**（这条决定草案能否被外审）：每条期望必须**能从 `依据` 列指向的外部物重演出来**，不接受"我认为应该填这个"。凡依据列写不出来的条目，**宁可不进草案**，也不要用判断填空。

**覆盖要求**：≥15 校夹具、每校 ≥20 期望字段；每校按**页面控件全集分层抽样**（必填/选填/拒填各占比），抽样规则另附一页说明。

**流程**：草案 → 我复核**推导链成立性**（不评"值好不好"）→ 我签 `oracle-F01.signed.json`（含 sha256 + 判定行）→ **草案全文转 GPT 独立审计**。

### 3.2 bench 实现（可与草案并行，但不得用未冻结的期望表跑绿）

`test/bench/`；输入 = `{夹具页, 档案, 期望字段表(已签), 允许拒填清单}`；走 `src/core/fill-pipeline.ts` **真实入口**；四分类按 **P1**（`越界填 > 填错 > 漏填`，"拒填"为正交维度带理由）；越界按 **P4 台账口径**（`registerWriteOwnership` 每次调用 + 每次 DOM 赋值点，区分 attempted/committed，**不得按尾态**）；判等独立（**P5**，不得复用生产 `isSemanticEqual`/`readNativeControlValue`）；报表脱敏（**P9**，只存计数/字段键/值形状/sha256）。
