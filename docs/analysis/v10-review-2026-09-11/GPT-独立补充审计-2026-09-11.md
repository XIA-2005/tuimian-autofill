### 2.2 当前提交协议的独立性缺口

`{夹具页, 控件定位, 期望字面值, precision, 依据}` 仍不足以闭合推导链。DOM 的 `name/id/label` 证明目标字段语义；`maxlength/pattern` 证明页面约束；码表证明代码—名称关系。三者都不能证明该用例选用的档案源值，也不能证明从源值到期望字面值的转换没有复用生产实现。

签名前，每条 oracle 至少还需增加并独立核验：

1. `fixtureSha256`：被审页面夹具的内容哈希；
2. `controlEvidence`：唯一定位、关联 label、required/optional、maxlength/pattern/选项集合；
3. `profileFixture`、`profileSha256`、`profilePath`：合成档案来源及字段路径；
4. `transformRule`：不依赖生产 `isSemanticEqual`、`readNativeControlValue` 或格式化函数的确定性规则；
5. `expectedLiteral` 与 `precision`：由“源值 + 页面约束 + transformRule”重新计算可得；
6. `refusalClass` 与理由：合法拒填须与允许拒填清单逐项对应；
7. `stratum`：required / optional / refused，用于验证每校分层覆盖而不是只挑易填字段。

第三方签名条件：所有文件哈希可复算、locator 在对应夹具中唯一、profilePath 在合成档案中存在、独立转换器重算值与 `expectedLiteral` 一致、每校不少于 20 项且覆盖三类分层、无真实个人值、无竞品目录作为输入。任一项不满足即拒签并具名到 caseId。

## 3. 竞品实际填对率为何当前不可测

本机正式包包含：

- `baoyan-native.exe` 与 Qt runtime；
- `bridge/python/python.exe` 和业务 Python；
- `worker/browser_worker/node_modules/playwright`；
- 浏览器扩展。

这说明“缺执行环境”不是唯一问题。但正式包不包含 `worker/browser_worker/test/`，其 `package.json` 的 `npm test` / `test:browser` 指向不存在的测试文件；本轮曾实跑 `npm test` 并以“Could not find `test/adapter_operation_matrix.test.js` …”退出 1，复审确认竞品目录未产生写入。该动作虽未造成实体修改，但包脚本存在生成缓存或改 lockfile 的潜在副作用，属于流程风险；今后不再在竞品目录执行任何脚本。`data/.production_no_test_fill` 又明确写明正式填写不得使用测试/哨兵来源。即使启动程序，也只能证明程序能启动，不能得到逐字段填对率。

要形成可发布的竞品实际填对率，必须同时具备同一批真实页面、同一份合成档案、逐字段独立 oracle、同一时点登录态，以及双方相同的 attempted/committed 记账口径。当前这些条件不存在，故依 P8 **不产出任何百分比或“谁更准”的数字结论**。此项应记为“当前不可测”，不是“永久不可测”；输入齐备后可重新开启。

## 6. 我方覆盖数字的独立复算

可复跑探针：`docs/analysis/v10-review-2026-09-11/probe-adapter-counts-gpt.cjs`。它对 `src/core/adapter-packages.ts` 通过 esbuild 内存打包后枚举 `SCHOOL_ADAPTER_PACKAGES`，不以源码文本中的 `pkg(` 次数代替运行时对象数，也不生成临时 bundle。

本次争议来自两个不同分母，应同时保留而不能互相覆盖：

```json
{
  "inventoryScope": {
    "allPackages": 73,
    "packagesWithForm": 72,
    "wildcardPackages": 3,
    "concreteHostsIncludingCrawlOnly": 70,
    "nonPlatformSchoolNamesIncludingCrawlOnly": 65
  },
  "formFillScope": {
    "concreteHosts": 69,
    "nonPlatformSchoolNames": 64
  },
  "excludedFromFormFillScope": [
    {
      "id": "nuaa-ssxly",
      "schoolName": "南京航空航天大学",
      "hosts": ["yzsbm.nuaa.edu.cn"],
      "roles": ["crawl-only"]
    }
  ]
}
```

分解为 `39 + 15 + 9 + 10 = 73`。此前“54 = 39 + 15”漏计 9 个复古系统生成包和 10 个通用映射生成包。因此：

- “108 域名 / 102 校”确实不能继续引用；
- “54 包 / 约 50 校”也不能定稿；
- 库存口径应写为：**73 个运行时包对象；72 个含 form；70 个含 crawl-only 的具体域名；65 个含 crawl-only 的去重非平台校名**；
- 严格 form-fill 口径应写为：**69 个可填写具体域名；64 个可填写非平台校名**；唯一排除项是仅含 `crawl-only` 的 `nuaa-ssxly`。

因此 DeepSeek 的 70/65 与 GPT 的 69/64 都可复跑；前者是全库存，后者是严格可填写范围。此前报告已经公开列出 `onlyCrawlOrShell: ["nuaa-ssxly"]`，不是隐藏排除规则，但“具体填报域名”一词确实不够精确，现已改为双口径。范围结论仍保持定性：“大体持平、无一方碾压”。
