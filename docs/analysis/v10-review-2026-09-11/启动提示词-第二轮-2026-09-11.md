## 4. 第三件事：F01 正确率基准设施

### 4.1 卡文要求（任务书 §3-F01，已吸收 P1–P9，照做）

`test/bench/`；输入 = `{夹具页, 档案, 期望字段表(审查者冻结), 允许拒填清单}`；走 `src/core/fill-pipeline.ts` **真实入口**；四分类按 **P1 优先级**（`越界填 > 填错 > 漏填`，"拒填"为正交维度带理由）；越界按 **P4 台账口径**（`registerWriteOwnership` 每次调用 + 每次 DOM 赋值点，区分 attempted/committed，**不得按尾态**）；判等独立（**P5**，不得复用生产 `isSemanticEqual`/`readNativeControlValue`）；报表脱敏（**P9**，只存计数/字段键/值形状/sha256）。

验收：`npm run bench` exit 0 + 报表落盘；**越界填绝对 0**（非基线）；负向自检 `--negative-overfill` 注入一次期望外写入 → exit 1 且具名；`npm run bench` **并入 `test:offline`**。

### 4.2 审查者补充前置（不可省）

1. **oracle 覆盖率分层**：≥15 校夹具、每校 ≥20 期望字段；每校按**页面控件全集分层抽样**（必填/选填/拒填各占比），抽样规则写入推导文档——防"只挑好填的字段"。
2. **越界检测只读接入**：bench 读 `registerWriteOwnership` 台账必须是**只读包装**，不得为 bench 改生产登记逻辑（否则与 INV-A1-a 互相污染）。
3. **确定性**：同夹具同档案 → 同四元组；任何随机/时间依赖须固定 seed 与时间基准。

### 4.3 oracle 提交协议（六字段，**已吸收 GPT 的改进**）

上一轮的五字段协议缺"档案源值 → 独立转换规则"这条证据链，审计者无法独立重演推导。**修订为六字段**：

```
{
  夹具页,
  控件定位,
  档案源值        (profile 路径 + 原值, 如 education.startDate = "2022-09"),
  独立转换规则    (如 2022-09 --maxlength=8--> 202209),
  期望字面值,
  precision,
  依据            (外部可核物: 夹具 DOM name/id/label、页面 maxlength/pattern、码表条目)
}
```

流程：你先出草案 → `docs/analysis/v10-review-2026-09-11/oracle-draft-F01.json` → 我复核**推导链是否成立**（不是"值好不好"）→ 我签 `oracle-F01.signed.json`（含 sha256 + 判定行）→ **oracle 全文转 GPT 做独立性审计**。
