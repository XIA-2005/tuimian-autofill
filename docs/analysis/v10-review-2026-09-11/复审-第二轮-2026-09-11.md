## 3. B-3（新发现）：tree-only 文件的**改动是静默的**

**先说清性质**：这不是 B-1 未交付。我的 B-1 原文只要求"**新增**文件可见"，执行者完整交付了。这是我在读工具代码时发现的**相邻缺口**，属于我这一轮的新增发现，不是它的欠账。

### 3.1 代码证据（`tools/v10-hashes.cjs`）

```

:109   const known = new Set([...Object.keys(expected), ...Object.keys(tree.files)]);
:116   控制台输出的口径串
```

**全仓 grep `tree.files` 只有上述 4 处**：写入（:87/:91）、判存在（:109/:142）。**`tree.files[p].sha256` 被写下之后，没有任何代码路径读过它。** `check()` 的漂移循环只遍历 `expected`（基线 135 ∪ 签名），tree 的 88 个文件**只参与"是不是新文件"的分类，不参与哈希比对**。

### 3.4 修法建议（约 5 行，复用已算好的数据）

不要无脑全量比对（会引入构建产物噪音）。用 `tree` 模式**已经在算**的 `dirty` 集合：

```js
// check() 内，与未声明新文件同一循环之后：
const dirty = new Set(gitLines(`git -c core.quotePath=false diff --name-only ${GRANDFATHER_REF} HEAD`));
for (const p of Object.keys(tree.files)) {
  if (!dirty.has(p)) continue;                    // 未改 → 不报（天然避开 build 噪音，未提交的生成物不进 diff）
  if (touchRes.some((r) => r.test(p))) { declared.push(p); }   // 声明过 → 视同已声明
  else { treeDrift.push(p); }
}
// 输出 TREE-DRIFT <path>，并计入 exit 1
```

**验收**：`check` 必须把 `.github/workflows/offline-gates.yml` 报为 `TREE-DRIFT`（它就是本轮 N-3 改过、且未声明的那个），同时在 F03 或新 touch-list 里补一条声明，报项随之归零。**负向自检**：临时改一个 tree-only 且未声明的文件（如 `.gitignore`）→ `TREE-DRIFT` + exit 1；还原 → 归零。

> **若执行者判断噪音风险不可接受**：必须（a）把该限制作为**具名残留限制**写进任务书与账本，附完整 88 文件清单与"其中 11 个为代码/治理类"的明示；（b）取得**用户书面接受**。仅口头默认不可。
