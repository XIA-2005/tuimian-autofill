## 1. 专项回答一：§"我方强项不得改坏"清单在 A1/A2 里**没有**被护栏保护

结论：**未受保护，且 A2 与两条存量链路存在硬冲突。** 不是"描述不够细"，是"按现卡文实施会破坏既有的写入正确性机制"。

### 1.1 A1 卡文对四条结构性验证机制零护栏 `[实测：行号已核]`

A1 要动 `filler.ts:134-138`（通用文本事件四件套）、`control-drivers.ts:33-38`（合同链事件三件套），并"补 `setInputValue` 的 `_valueTracker` 清理一致性"。但以下四处**一个字的护栏都没有**：

| 机制 | 位置 | 与 A1 的冲突面 |
|---|---|---|
| `conditionalRestore` 第 6 道门要求 `driver === 'text'` | `filler.ts:600-636` | A1 若引入"按字段风险分事件集"并给字段打标签，`driver` 语义可能被改写 → 该门失效 |
| ownership 快照登记 | `registerWriteOwnership`（`filler.ts` 写入链尾部） | A1 改变"什么算一次写入"→ ownership 快照与 `stableVerifyWritten`（`task-executor.ts:171-184`）比对错位 |
| settle 稳定回读 | `task-executor.ts:33-78`（1500ms / 30ms 轮询二次确认） | `_valueTracker` 清理会改变页面框架看到的写入时序 → 稳定回读结论可能翻面 |
| 回读取值口径 | `readNativeControlValue`（`filler.ts:350-367`） | 事件集合变化后若回读时机改变，"写对又重置"可能被误判为成功 |

**后果**：A1 一旦让 `conditionalRestore` 不再触发或误触发，即回到 v9 之前的"清空仍报 filled"缺陷类——这是被历史审查否定过的缺陷模式。

**修订要求**：A1 必须显式列出**不可变式（invariants）**并各配一条负向断言（改坏即 exit≠0）：
- (a) ownership 登记时机与内容不变；
- (b) `conditionalRestore` 的 6 道门语义不变，尤其 `driver === 'text'`；
- (c) `_valueTracker` 清理不得改变 settle 稳定回读结论；
- (d) 事件集合变化不得改变 `readNativeControlValue` 的读数。

### 1.2 A2 与世界（world）归属：核心机制**可能根本不可移植** `[推断——必须在 A2 前先验证]`

竞品把 `window.setTimeout` patch 写在 `page_protocol_fill.js`（`:8118-8127`）。该文件在 `manifest.json` 第 4 段，**未声明 `world` → 默认 ISOLATED**。隔离世界的 `window.setTimeout` patch **拦不到页面自己调用的 `setTimeout(__doPostBack)`**（页面定时器在 MAIN world）。

我方要拦页面定时器，必须放进 MAIN world——`src/world/main-world.ts` 已具备该条件（`world:"MAIN"`、`document_start`、`all_frames:true`）。**但一旦进 MAIN world 就与页面共享全局，我方与页面的定时器无法用"命名空间"天然区分。**

→ **A2 现卡文未指定机制落在哪个 world、也未指定如何区分"页面定时器"与"我方定时器"。** 这是必须先做只读诊断的前置问题，不是实现细节。

### 1.3 A2 与存量链路的**两处硬冲突** `[实测]`

**(a) 我方自己有 33 处 `setTimeout`——全局 patch 会打断它们：**

| 文件 | setTimeout 处数 | 其中关键项 |
|---|---|---|
| `src/content/index.ts` | **16** | 补填轮次 `followupDelays = [2500, 7000, 15000]`（`:2352` 附近） |
| `src/core/date-drivers.ts` | **11** | 350ms 自愈重写（`:184-192`） |
| `src/core/filler.ts` | 3 | — |
| `src/core/task-executor.ts` | 1 | settle 轮询 |
| `src/core/dynamic-table.ts` | 1 | `:12` sleep |

竞品能全局 patch 是因为它的定时器在 Python 侧（薄扩展）；**我方的定时器就在扩展内**。照抄 = 打断自愈重写与补填轮次。

**(b) stub `__doPostBack` 会打断我方"主动回发加行"链路：**

`src/core/dynamic-table.ts` 里有一条**为了把表格行写进去**而主动回发的链路：
- `:104 fireStandardPostback`（标准整页回发，等价 `__doPostBack`）
- `:126-129 isDoPostbackAction`（识别 `javascript:DoPostback` 型按钮）
- `:149-213 clickPageAction`（三策略轮换：标准回发 / 主世界 `location.href=javascript:void(...)` / 原生 click）
- `:885-888` 北邮式逐行 DoPostback「添加」落库

**被 stub 掉 = 表格填不进去。** 现卡文只说"填写窗口内 stub"，未排除加行时段。

**修订要求**：A2 **否决并拆为两张卡**：
- **A2a（只读诊断）**：枚举页面上真实的延迟回发来源，用探针证明"是页面的 `setTimeout` 还是我方的"，输出 world 归属结论与 patch 作用域方案；
- **A2b（抑制窗口）**：必须**显式排除**（i）`dynamic-table` 加行时段、（ii）`content/index.ts` 补填轮次；且抑制窗口与 stash 键**按 frame 隔离**（否则破坏 `all_frames:true` 的每 frame 独立填写强项）。

### 1.4 零桌面依赖强项：A 阶段不威胁，**C2/D1 威胁** `[推断]`

`D1` 的 CDP 采集器与 `C2` 的 OCR 强化**不得进入扩展运行时依赖**：不得写进 `manifest.json` 的 `host_permissions`、不得被 `src/` 任何文件 import。任务书需加这条护栏，否则"零桌面依赖"会在不知不觉中失守（我方现在唯一的本地服务耦合是 `captcha-bridge.ts` 的**可选** `localhost:18765`，默认 route='A' 不碰）。

## 2. 专项回答二：F01「越界填恒为 0」作为硬门禁的**8 条绕过路径**

现卡文把"越界填恒为 0"当作硬门禁，方向正确，但**当前设计可被绕过**：

## 4. 错口径（5 条）

1. **编号引用已漂移 `[实测]`**：执行者引"§2 我方强项不得改坏"，源文档该清单在 **§4**。→ 除补稳定 ID 锚点外，**冻结版必须带版本号与哈希**，后续引用一律用 ID 不用章节号。
2. **F01 四指标无优先级**：`越界填=0`、`填错=0`、`漏填最小化`会互相打架——**A5 本身就是拿漏填换正确率**。建议冻结次序：**越界填=0 ＞ 填错=0 ＞ 拒填理由可解释 ＞ 漏填最小化**。不冻结则每张卡都能挑一个指标变好、另一个变坏来交差。
3. **"正确率"未定义分母**：是"应填字段数"还是"页面控件数"？漏填/拒填是否进分母？→ 必须写死，否则同一组数字可得出任意结论。
4. **bench 判等不得复用生产代码**：若 F01 用 `value-semantics.ts` 的 `isSemanticEqual` 判断"填对"，则该函数的缺陷在生产与 bench 中**同时成立、永不可见**。→ bench 须用独立期望值表（逐字段字面期望 + precision），"实际值提取"也不得复用 `readNativeControlValue`。
5. **禁止任何卡引入与竞品的百分比对比**：竞品**从未公布逐字段正确率**（只公布字段级 gap 量化：`gap_count` 4596、53.2% 缺 `control_kind`、67% 选项未采集），两者不可相减。此条任务书已有，需**提升为"禁止项"清单里的硬约束**并配一条会在出现对比数字时失败的断言。
