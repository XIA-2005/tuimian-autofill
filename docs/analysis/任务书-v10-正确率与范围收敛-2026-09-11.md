### 1.4 勘误（本方独立复验结论，审查者接受为事实底座）
1. **[VB] 135 文件哈希门禁**：工具 `tools/verify-v9-hashes.cjs` 采用"基础清单+v9 后续覆盖"**分层**设计（实测存在 followup 覆盖机制），且**未接入任何 npm 门禁**（`grep package.json/test/regression` 零命中）。故"Phase A 必致全门禁红"不成立；真实问题是**治理缺口**：v10 无重签责任人 → 由 F04 卡补。Phase A 全部 9 个目标文件确在清单内（实测 9/9 IN）。
2. **[VB] 竞品回发抑制的世界归属**：审查者"竞品在 ISOLATED 拦不到页面定时器、机制可能不可移植"与实物不符——竞品在 `page_world_bridge.js`（manifest 声明 `world:"MAIN"`、`all_frames:true`）的 `:1810-1845` 做 `__doPostBack` stub 与 setTimeout 过滤；其 `page_protocol_fill.js:8118-8127` 的 setTimeout 包装处理的是**隔离世界自身派发的事件回调**（`fireValueEvents` 触发的 inline handler 字符串回页面世界前）。文件头自述"隔离世界改不了 confirm/__doPostBack/form.submit，DO NOT 只改隔离世界"。**结论不变但理由修正**：我方 A2b 必须落 MAIN（`src/world/main-world.ts` 已具条件），且需处理"MAIN 内 stub 与自家 `fireStandardPostback`（直接设 `__EVENTTARGET`+form.submit）的互斥"——`HTMLFormElement.prototype.submit` 若在 MAIN 被 stub 会打断加行链。此设计约束交 A2a 探针实证。
3. **[VB] F03 挂起根因已定位**：`test/.v9-tmp-run.mjs` 打包时**未标 `external:['esbuild']`**（运行输出自带 esbuild require.resolve 警告），esbuild 被内联进 155KB bundle 后找不到原生二进制 → 测试内部 `v9-protocol.test.ts:59` 的 `buildSync`（构建真实 background bundle 进 VM）同步死锁。诊断 runner 打印 "import bundle" 后 25s 无输出实证。**而 `build.mjs` 测试管线已配 `external:['jsdom','playwright','esbuild']`（build.mjs:70）——走正式管线接入 run.ts 不会挂。** 84 用例本身未证明是红的。

## 2. 度量定义与优先级（冻结，P 系列）

- **P1 四分类互斥且穷尽**（判定优先级自上而下，先命中先归类）：`越界填 > 填错 > 漏填`；"拒填"为**正交维度**（带理由），不参与三选一；被拒控件必须仍出现在控件全集报表中（堵 skip 名单漂移）。
- **P2 指标优先级**：**越界填=0 ＞ 填错=0 ＞ 拒填理由可解释 ＞ 漏填最小化**。任何卡以"漏填变多"为代价修正确率是**预期行为**，以"填错/越界增加"为代价不可接受。
- **P3 正确率分母**：`正确率 = 填对 / (期望应填字段数)`；漏填、填错进入分母；合法拒填（允许拒填清单内）**不进分母**；越界填不进分母但单独硬归零。
- **P4 越界判定口径**：从**生产写入台账**（`registerWriteOwnership` 每次调用 + 每次 DOM 赋值点）统计 `attempted` 与 `committed`；抛错前已提交的部分写入计入越界；**不得按尾态判定**（conditionalRestore/页面重置擦掉的也算越界）。越界=0 是**绝对 0**，不设基线赦免。
- **P5 判等独立**：bench 期望表为逐字段字面期望+precision；判等与实取值**不得复用**生产 `isSemanticEqual`/`readNativeControlValue`（防共享缺陷）。bench 自带最小读取器。
- **P6 用例作者≠实现者**：期望表/允许拒填清单由审查者（DeepSeek）复核签名后冻结；执行者不得单方面修改已冻结期望。
- **P7 覆盖下限**：每张卡触及的页面/适配包在 bench 中至少 1 条用例；报表枚举**页面全部控件**（含被拒者+理由）。
- **P8 禁止虚假对比**：任务书/账本/bench 报表禁止出现"我方 X% vs 竞品 Y%"或竞品正确率数字（竞品从未公布逐字段正确率，只有 gap_count 4596/53.2% 缺控件/67% 缺选项这类**不可相减**的字段级缺口）。bench schema 校验：出现 `competitorAccuracy` 类字段即 exit 1。
- **P9 落盘脱敏**（承接 `fill-telemetry.ts:42/285/319` 既有纪律与 `v7-telemetry.test.ts` 守卫）：F01/D2 逐字段报表只存**计数/字段键/值形状（正则化，如 `\d{4}-\d{2}`）/sha256 摘要**，禁止字段原文值与页面原文落盘。
