## 2. 度量定义与优先级（冻结，P 系列）

- **P1 四分类互斥且穷尽**（判定优先级自上而下，先命中先归类）：`越界填 > 填错 > 漏填`；"拒填"为**正交维度**（带理由），不参与三选一；被拒控件必须仍出现在控件全集报表中（堵 skip 名单漂移）。
- **P2 指标优先级**：**越界填=0 ＞ 填错=0 ＞ 拒填理由可解释 ＞ 漏填最小化**。任何卡以"漏填变多"为代价修正确率是**预期行为**，以"填错/越界增加"为代价不可接受。
- **P3 正确率分母**：`正确率 = 填对 / (期望应填字段数)`；漏填、填错进入分母；合法拒填（允许拒填清单内）**不进分母**；越界填不进分母但单独硬归零。
- **P4 越界判定口径**：从**生产写入台账**（`registerWriteOwnership` 每次调用 + 每次 DOM 赋值点）统计 `attempted` 与 `committed`；抛错前已提交的部分写入计入越界；**不得按尾态判定**（conditionalRestore/页面重置擦掉的也算越界）。越界=0 是**绝对 0**，不设基线赦免。
- **P5 判等独立**：bench 期望表为逐字段字面期望+precision；判等与实取值**不得复用**生产 `isSemanticEqual`/`readNativeControlValue`（防共享缺陷）。bench 自带最小读取器。
- **P6 用例作者≠实现者**：期望表/允许拒填清单由审查者（DeepSeek）复核签名后冻结；执行者不得单方面修改已冻结期望。
- **P7 覆盖下限**：每张卡触及的页面/适配包在 bench 中至少 1 条用例；报表枚举**页面全部控件**（含被拒者+理由）。
- **P8 禁止虚假对比**：任务书/账本/bench 报表禁止出现"我方 X% vs 竞品 Y%"或竞品正确率数字（竞品从未公布逐字段正确率，只有 gap_count 4596/53.2% 缺控件/67% 缺选项这类**不可相减**的字段级缺口）。bench schema 校验：出现 `competitorAccuracy` 类字段即 exit 1。
- **P9 落盘脱敏**（承接 `fill-telemetry.ts:42/285/319` 既有纪律与 `v7-telemetry.test.ts` 守卫）：F01/D2 逐字段报表只存**计数/字段键/值形状（正则化，如 `\d{4}-\d{2}`）/sha256 摘要**，禁止字段原文值与页面原文落盘。
